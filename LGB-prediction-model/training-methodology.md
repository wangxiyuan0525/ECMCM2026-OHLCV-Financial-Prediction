# LightGBM 建模与训练管线

> 从 250 维因子到交易信号：五策略对比实验 → 因子组贡献分解 → IC 最优迭代选择 → 三种子集成 → 模型部署

---

## 1. 训练框架总览

### 1.1 核心流水线

```
30个dataset ──→ 时序切分(Train 70% | Gap 60bar | Valid 15% | Gap 60bar | Test 15%)
                    │
                    ├──→ 训练集拼接 (27 dataset × ~900K行 ≈ 24.6M行 × 250维)
                    │         │
                    │         ├── LightGBM 训练 (500棵树, IC目标, moderate权重)
                    │         ├── IC曲线监控 → 手动选择最优迭代轮数
                    │         └── 3-seed Ensemble → 平均融合
                    │
                    ├──→ 验证集评估 (All / Normal / Extreme 三组IC)
                    ├──→ 特征重要性分析 (Gain + Split)
                    └──→ Holdout评估 (最后3个dataset, 训练时完全不可见)
```

### 1.2 时序切分与防泄漏

采用带间隔的时序切分（Gap Split），在训练/验证/测试之间各留 60 分钟的缓冲区，杜绝因时序重叠导致的信息泄露：

| 区间 | 占比 | 说明 |
|------|------|------|
| Train | ~70% | 前70%数据，用于模型拟合 |
| Gap | 60 bars | 缓冲间隔，防止时间窗口特征跨区泄漏 |
| Valid | ~15% | 中间15%，用于IC最优迭代选择 |
| Gap | 60 bars | 二次缓冲 |
| Test | ~15% | 末尾15%，最终评估（训练时完全不可见） |

### 1.3 极端行情权重策略

赛题要求对极端行情（如闪崩、暴涨）给予额外关注。我们在样本权重层面做了三档差异化配置：

| 模式 | Extreme权重 | Extreme占比 | Normal IC效果 |
|------|------------|------------|--------------|
| aggressive | 3.0× | 35% | 深度为负（~-0.08） |
| **moderate** ✓ | **1.5×** | **15%** | **接近转正（~-0.05）** |
| neutral | 1.0× | 自然比例 | 正常，但Extreme IC偏低 |

最终选择 **moderate 模式**：在保证 Extreme IC 优异（Ret5=0.23+, Ret60=0.36+）的同时，将 Normal IC 从深度负值拉回至接近零轴，避免了模型只在极端行情有效而在常态失效的偏斜。

## 2. 五策略对比实验

### 2.1 实验设计

为确定 250 维因子的最优构成，我们设计了五版因子组合（从 60 到 250 维递增），在同一 LightGBM 框架下严格对比：

| 策略 | 维度 | 因子来源 | 训练规模 | 目的 |
|------|------|----------|---------|------|
| **A: Ultra-Compact** | ~60 | 仅最高质量因子 | QuickRun (20K×30, 400树) | 测试极简方案下限 |
| **B: SP-Top** | ~80 | SP有符号幂变换核心 | QuickRun | 验证SP因子独立贡献 |
| **C: Elite-Hybrid** | ~173 | SP+wxy+AH+Base混合 | 全量数据 (500树) | 中大规模混合效果 |
| **D: Pure-wxy** | ~109 | wxy_new新增因子+精选base | 全量数据 | 验证新增因子的独立价值 |
| **E: Balanced-250** | 250 | 全覆盖最大因子集 | QuickRun (全量OOM) | 测试最大因子池上限 |

> **注**：Strategy E 全量数据训练因内存不足崩溃（需 22.9 GiB），仅完成 QuickRun 验证。

### 2.2 IC 对比结果

| 策略 | 维度 | Ret5 Extreme IC | Ret60 Extreme IC | Ret5 Normal IC |
|------|------|----------------|-----------------|---------------|
| A (Ultra-Compact) | 60 | — | — | — |
| B (SP-Top) | 80 | — | — | — |
| C (Elite-Hybrid) QuickRun | 173 | 0.233 | 0.362 | -0.058 |
| C (Elite-Hybrid) 全量 | 173 | ~0.23 | ~0.37 | ~-0.05 |
| D (Pure-wxy) 全量 | 109 | 0.166 | 0.201 | -0.044 |
| E (Balanced-250) QuickRun | 250 | 0.235 | 0.364 | -0.059 |

### 2.3 关键发现

1. **173维 ≈ 250维**：Strategy C 与 E 的 QuickRun IC 几乎一致（Extreme IC 差值 < 0.002），说明从 173 维到 250 维新增的 77 个因子贡献极低，主要来自 L4 衍生和 Extra SP 中的冗余项。

2. **wxy_new 无法替代 SP+Base**：Strategy D（纯 wxy_new）的 Ret5 Extreme IC = 0.166，显著低于混合策略的 0.23+。wxy_new 因子（分数阶差分、卡尔曼滤波等）提供独特信号但覆盖范围有限，必须与 SP 和 Base 因子配合使用。

3. **Normal IC 是核心瓶颈**：所有策略的 Normal IC 均为负值（约 -0.05），而 Extreme IC 优秀（0.23~0.37），说明模型在常态行情下的预测力尚需提升。这指导了后续 moderate 权重策略和噪声因子剪除方向。

4. **250维全量训练 OOM**：24.6M行 × 250维的 float32 矩阵需要 22.9 GiB 内存，超出本地机器（32GB RAM）的可用空间。这验证了因子剪枝和分批加载优化的必要性。

## 4. 模型训练技术细节

### 4.1 LightGBM 超参数

| 参数 | Ret5 | Ret60 | 说明 |
|------|------|-------|------|
| n_estimators | 500 | 500 | 全量训练；QuickRun = 400 |
| num_leaves | 63 | 127 | Ret60 更复杂，叶子更多 |
| learning_rate | 0.03 | 0.02 | Ret60 保守学习防过拟合 |
| max_depth | -1 | -1 | 不限制深度 |
| min_child_samples | 200 | 200 | 防过拟合 |
| subsample | 0.85 | 0.85 | 行采样 |
| colsample_bytree | 0.85 | 0.85 | 列采样 |
| reg_alpha | 0.05 | 0.05 | L1 正则 |
| reg_lambda | 1.0 | 1.0 | L2 正则 |

### 4.2 v2 关键改进：IC 最优迭代选择

LightGBM 内置的早停（early stopping）基于 L2 损失（MSE），但赛题的评价指标是 IC（Pearson 相关系数）。L2 最优的迭代轮数往往不等于 IC 最优：

```
L2损失曲线: 持续下降, 早停触发在 iter≈200
IC评估曲线: iter≈350 时达到峰值, 随后缓慢衰减
→ L2早停导致 IC 损失约 0.02~0.03
```

**v2 修复方案**：训练时不使用 LightGBM 内置早停，而是训练全部 N 棵树后，从 `evals_result_` 中读取 IC 监控曲线，手动选择 IC 峰值对应的迭代轮数作为 `best_iteration_`。

```python
# v2 核心代码
ic_history = model.evals_result_['valid_0']['ic']
best_iter = int(np.argmax(ic_history)) + 1
model.best_iteration_ = best_iter
```

### 4.3 IC 自定义目标函数

除 MSE 回归外，我们还实现了 IC 直接最大化的自定义目标函数，提供梯度/Hessian 近似：

$$ \text{grad} = -\left(\frac{y}{\text{denom}} - \rho \cdot \frac{p}{\sum p^2}\right), \quad \text{hess} = \frac{1}{\text{denom}} $$

其中 $\rho$ 为当前预测与真实标签的 Pearson 相关系数，$p$ 为去均值后的预测值，$y$ 为去均值后的标签。

### 4.4 三种子集成

使用不同随机种子（2026, 42, 123）训练三个独立模型，预测时取三者的算术平均：

$$ \text{Signal} = \frac{1}{3}\sum_{i=1}^{3} \text{Model}_{\text{seed}_i}(\text{Factors}) $$

集成带来的收益：单一模型在不同 seed 下 IC 波动约 ±0.005，集成平均后稳定在均值附近，有效降低了随机性带来的性能抖动。

## 5. 评估体系

### 5.1 三级 IC 评估

| 分组 | 定义 | 意义 |
|------|------|------|
| **All** | 全部样本 | 综合预测能力 |
| **Normal** | 非极端行情样本 | 常态下的预测稳定性（最关键的瓶颈指标） |
| **Extreme** | 极端行情样本（赛题标注） | 极端行情下的预测力（赛题重点关注） |

### 5.2 Holdout 验证

训练时保留最后 3 个 dataset（dataset27/28/29）作为 Holdout 集，在整个训练过程中完全不可见。仅在所有训练和验证完成后，用 Holdout 做最终评估，确保泛化能力评估的无偏性。

### 5.3 特征重要性双维度

- **Gain Importance**：特征在所有树中分裂带来的总损失下降，衡量特征的"预测贡献"
- **Split Importance**：特征被用作分裂节点的次数，衡量特征被模型"使用的频率"

两者结合判断：高 Gain + 低 Split 的特征是"低频高价值信号"；低 Gain + 高 Split 的特征可能是"噪声型高频分支"。

## 6. 模型部署

### 6.1 模型导出

训练完成后自动生成三份文件用于线上部署：

| 文件 | 格式 | 用途 |
|------|------|------|
| `models_ret5_ret60.joblib` | joblib 二进制 | 本地快速加载，包含 Ret5+Ret60 模型与元信息 |
| `model_ret5.txt` / `model_ret60.txt` | LightGBM booster txt | 跨版本兼容，可被任何 LightGBM 版本加载 |
| `experiment_meta.json` | JSON | 完整实验配置、超参数、IC汇总 |

### 6.2 线上推理

`signal-generation/generate_signals.py` 的推理流程：

1. 加载 `models_ret5_ret60.joblib` 恢复模型
2. 从 factor.py 输出的 (T, 250) 因子矩阵取前 `feature_count` 列
3. NaN/Inf 填充为 0，clip 到 [-1e6, 1e6] 防止数值溢出
4. 如果是集成模型列表，取各子模型预测均值；否则单模型预测
5. 输出 (T, 2) 信号矩阵：列0=Ret5信号，列1=Ret60信号

### 6.3 与 factor.py 的接口契约

```
factor.py                           predict.py
─────────                           ──────────
generate_factors(name, data)   →   generate_signals(name, factors)
     │                                    │
     │ (T, 5) OHLCV                       │ (T, 250) float32
     │         ↓                          │         ↓
     │ (T, 250) float32 ───────────────→  │ (T, 2) float32
```

两个函数被赛题测评系统隔离调用，无共享状态。因子计算代码与预测代码在数学逻辑上必须严格等价于本地训练时的环境。

## 7. 策略选择逻辑链

```
Step 1: 构造五版因子组合（A→E，从60到250维递增）
  ├─ A(60): 测试极简方案下限
  ├─ B(80): 验证SP因子独立贡献
  ├─ C(173): 测试混合策略协同
  ├─ D(109): 验证新增因子独立价值
  └─ E(250): 测试最大因子池上限

Step 2: 统一LightGBM框架训练
  ├─ QuickRun (A/B/C/E): 快速迭代，400棵树
  └─ 全量数据 (C/D): 验证泛化，500棵树

Step 3: 横向对比IC
  ├─ 173维 ≈ 250维 QuickRun IC → 新增77维贡献极低
  ├─ D(109维) Ext IC << C(173维) → wxy_new不能替代SP+Base
  └─ Normal IC全部为负 → 需moderate权重+剪除噪声

Step 4: 特征重要性分层评估 → 剪枝决策
  ├─ SP贡献>50% → 全部保留 (70/70)
  ├─ wxy_new贡献12-15% → 全部保留 (22/22)
  ├─ AH贡献5-8% → 精选15/21
  ├─ L4贡献~0% → 仅保留4/20
  └─ Extra SP贡献~0% → 仅保留15/17转至SP组

Step 5: 输出最终250维方案
  └─ 7组架构, moderate权重, 3-seed集成
```
